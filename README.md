# 本地作品库 · JPAV Library

Windows 优先的个人作品元数据与本地视频管理软件。当前版本 **0.7.0 / Phase 3 扩展**，六个开发阶段的本地功能已接通。在线 DMM/FANZA 同步仍取决于用户凭据、地区和该来源的实际覆盖范围。

## 已实现

- 添加、编辑、移除女优资料；保存常用名、日文名、别名、头像路径。
- 原生文件夹选择器，可修改目录、打开资源管理器，也支持暂时离线的目录。
- 按常用名、日文名、别名搜索。
- 后台扫描当前目录及子目录，可取消，可配置递归和视频扩展名。
- 从文件名识别标准番号，支持大小写、全半角、横线/下划线/空格/无分隔符，以及 FC2-PPV 格式。
- 展示已识别、无法识别、多个候选、同番号多个文件，支持搜索和筛选。
- 手动指定番号并保留修正，也可恢复自动识别；不会重命名视频文件。
- 每位女优可从 UTF-8 JSON/CSV 导入作品番号、标题、发行日期及其他元数据；可选用本人配置的 DMM API 凭据在线查询。
- 同一作品跨数据源合并，支持多人作品关联、来源身份确认、分页完整性校验和同步历史。
- 以标准番号匹配本地文件与已收录作品；显示已收藏、缺少、最新作品、完成度和同步新增数。重复文件只计一部作品。
- 按女优忽略不需要收藏的作品；人工修正番号后重新匹配。有歧义的文件不会自动算作收藏。
- 首页总览支持按最近更新、完成度、作品数、缺少数排序；全局搜索女优、番号、标题和匹配的本地路径。
- 作品库可按状态筛选和发行日期、番号、首次收录时间排序；封面由用户按需缓存，不自动批量请求。
- SQLite 一致性备份、验证后恢复、恢复前安全副本、本地轮转日志及可选自动更新间隔。
- SQLite 持久化、增量迁移、唯一性约束、事务回滚、同数据目录进程锁。
- 不读取视频内容，不移动或删除本地视频。未同步统计显示“待同步”。

## 扫描操作

选择女优 →「扫描 / 本地文件」→ 确认扩展名及是否扫描子目录 →「开始扫描」。默认支持 `.mp4 .mkv .avi .mov .wmv .ts .m2ts .flv .webm`。

扫描只枚举目录项并保存文件名、路径和解析结果，不打开视频、不计算哈希、不采集大小/创建修改时间，也不调用 ffprobe。数据库中的 first_seen/last_seen 是软件扫描时间，不是视频的文件时间。目录类型和链接检查只用于安全遍历。

只有完整成功的扫描会更新文件记录；取消、离线目录、无权限或部分失败都会保留上次成功结果。缩小扫描范围（关闭递归或减少扩展名）不会把范围外文件判为丢失。符号链接和目录 junction 会跳过。修改女优目录后，旧目录记录可在「历史未见 / 旧目录」中查看。

同番号多个文件只是提示，不代表内容相同。手动修正按原路径保存；文件改名或移动后不会猜测旧映射。扫描后只对当前女优作品库执行番号匹配；当前已绑定来源没有该番号时显示为「当前作品来源未收录」。这表示元数据来源覆盖范围之外，不能推断作品不存在；请先绑定更多厂牌来源或导入自己的公开目录。详细行为及限制见 [Phase 2 说明](docs/phase2.md)。

## 作品库同步（Phase 3）

选择女优 →「作品库 / 同步」→「自动检索单人作品」。只填写中文名也可以；软件会尝试使用内置中日别名、用户别名和同字姓名查找 S1 官网身份，并在已配置 DMM API 凭据时查找 DMM/FANZA 身份。唯一且完全匹配时会自动绑定，并把查到的日文名保存回女优资料；身份重名或无法确认时会提示，不会猜测。每个来源分别完整读取作品列表与出演者名单，按番号合并；默认列表只显示非合集的单人作品。

JSON 可以是作品数组，也可以是带 `movies` 数组的对象；CSV 第一行是列名。必填 `code` / `番号`，其他常用列为 `title` / `标题`、`release_date` / `发行日期`（`YYYY-MM-DD`）、`manufacturer` / `制作商`、`publisher` / `发行商`、`series` / `系列`、`cover_url`、`detail_url`、`external_id`。所有导入文件使用 UTF-8，最多 50 MB。[查看示例 JSON](examples/actress_catalog.example.json)。每份导入文件视为当前所选女优的一个来源；再次导入同一路径会更新对应记录。

DMM API 使用运行进程的 `DMM_API_ID` 和 `DMM_AFFILIATE_ID` 环境变量，不写入 SQLite、导出文件或日志。手动来源身份仍可在界面确认；自动检索仅接受唯一且完全同名的候选。该接口需要 DMM 会员、Affiliate 和 API 使用登记，且有地区访问限制；此开发环境无法进行带真实凭据的在线联调。安装和使用不要求配置 DMM，离线导入可独立使用。详见 [Phase 3 数据源说明](docs/phase3.md)。

已收录数量是来源返回的记录数，不保证覆盖该女优的全部发行作品。

官网自动检索的统计口径只包含出演者名单确认只有该女优一人的作品。作品名含有 `BEST`、`ベスト`、`総集編`、`コンプリート`、`COLLECTION`、`合集` 等明确合集标记时，会保留在列表中但自动标记为「合集（不统计）」；详情页列出多位女优时标记为「多人企划（不统计）」。来源缺少出演者名单时整次同步失败，旧数据保持不变。S1 来源还提供「S1 邻号补查」：程序会围绕已发现的番号检查相邻编号，并要求候选详情页包含该女优的官方资料页链接才会纳入，避免把同厂牌其他女优作品计入。建议从范围 1 或 2 开始。

可用 `scripts/export_s1_catalog.py` 从 S1 官网公开女优页生成本地导入文件。[翼舞 S1 单人作品核验快照](examples/tsubasa-mai-s1-solo-verified.json)收录 28 个番号，逐条核对了 S1 官方详情页的出演者；这是 S1 范围内的快照，不包含其他片商。作品库窗口也保留「绑定 S1 官网身份」和「更新 S1 官网目录」：粘贴资料页 URL 或直接输入日文名，确认身份后即可分页读取；每页会校验官网总数和详情页，只有完整读取才写入数据库。

## 收藏匹配（Phase 4）

先导入或同步作品库，再扫描对应目录（也可反过来）。软件以番号自动匹配，作品库窗口可筛选「已收藏」「缺少」「已忽略」「最新作品」，并可对选中作品切换忽略。扫描窗口保留无法识别、库中不存在及同番号多个文件供核对。文件名有歧义时只能人工指定番号，不会自动猜测标题。

完成度 = 已收藏的非忽略作品 ÷ 非忽略作品总数。首次同步属于基线，后续同步新增数才显示为更新。尚未扫描当前目录时显示「待扫描」；更换目录后旧扫描结果不计入当前收藏。详见 [Phase 4 说明](docs/phase4.md)。

## 总览、搜索与封面（Phase 5）

首页显示每位女优的收藏、缺少、完成度和最新番号，支持四种排序。「全局搜索」可按女优名、番号和标题查询，结果展示收藏状态与本地路径，双击可打开相应作品库。作品库支持状态筛选、日期/番号/首次收录排序与选中作品封面按需缓存；只接受 HTTPS 图片，限制类型、大小和尺寸，不读取视频内容。文件大小排序不可用，因为扫描按用户要求只处理文件名。

## 备份、恢复与设置（Phase 6）

左侧「备份与恢复」可导出完整 SQLite 快照，包含所有资料、作品、扫描记录与人工修正，不包含视频文件和可重建的封面缓存。导入前检查 SQLite 完整性及数据库版本；恢复前自动把当前库保存到数据目录的 `backups` 文件夹。建议仍定期把备份复制到其他磁盘。

「设置」显示数据库、封面缓存、日志、扫描规则和数据源状态。视频扩展名与递归开关在扫描窗口修改。自动更新间隔默认为 0（手动）；设为正数后，对已绑定的 S1 来源及已配置凭据的 DMM 来源定时检查。代理沿用系统或 `HTTPS_PROXY` 环境变量。日志写入本机 `logs`，轮转保留，不记录视频文件名或 API 凭据。详见 [Phase 5/6 说明](docs/phase5-6.md)。

## 运行（PowerShell）

需要 Python 3.11+。在本项目目录执行：

当前固定 PySide6 6.8.3，已在本机 Python 3.12.7（Anaconda）验证；6.11.2 在此环境出现 Qt DLL 加载失败，暂不升级。

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
.\.venv\Scripts\python -m av_library
```

也可使用 `powershell -ExecutionPolicy Bypass -File .\run.ps1`。依赖安装完成后正常运行无需联网。

自定义数据目录：

```powershell
.\.venv\Scripts\python -m av_library --data-dir "D:\PrivateLibrary"
```

默认数据库在 `%LOCALAPPDATA%\JPAVLibrary\library.sqlite3`，封面、备份和日志分别在同级 `covers`、`backups`、`logs`。数据不放在源码目录，不提交 Git。切换 `--data-dir` 会打开独立资料库，不自动搬迁原有数据。

Windows 可用 `powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1` 生成 `dist\JPAVLibrary\JPAVLibrary.exe`。这是可携带的程序目录，用户数据仍默认保存在 `%LOCALAPPDATA%`。

## 设计与后续阶段

详见 [需求、架构、算法、Provider 与 MVP 计划](docs/architecture.md) 和 [完整目标 Schema](docs/schema-target.sql)。当前运行的迁移位于 `src/av_library/db/migrations.py`，请勿把目标 Schema 直接应用到真实数据库。
