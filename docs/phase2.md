# Phase 2：仅文件名扫描

用户需求调整优先于初稿：本地扫描只使用视频文件名，不读取视频内容，不采集大小、文件创建/修改时间、视频长度、分辨率或编码，不使用 ffprobe。保留完整路径以区分同名文件、定位文件和记忆人工修正。

## 实现

- `scanner/files.py`：`os.scandir` 显式栈遍历；大小写无关的扩展名筛选；不跟随符号链接与目录 reparse point；逐步取消、读取失败汇总。目录属性查询只用于判断类型及避免循环，不进行文件内容读取。
- `parsing/codes.py`：`CodeRule` 注册表，高优先级特殊规则覆盖同一字符范围的通用规则。输入做 NFKC、大小写、横线归一化；只使用文件 basename，不使用父目录；保留数字前导零；多个不同番号转人工确认。通用标准格式与 FC2-PPV 是当前内置规则，其他厂商格式可新增独立规则及用例。
- `services/scanning.py`：线程独立 Session；完整结果以单事务更新；维护历史记录、人工修正、扫描设置。不在扫描期间持有数据库事务，避免文件系统访问阻塞资料库。
- `ui/scan_dialog.py`：后台 QThread、明确投递至 UI 线程的 Qt Slot、进度/取消、筛选/搜索、手动番号及恢复自动。请求关闭时先取消，线程退出后再关闭，避免线程对象被提前销毁。

## 数据库迁移 v2

不修改 v1 迁移，在 v2 新增 `local_files`、`scan_history`，移除过时的 `read_ffprobe` 设置。首次启动自动升级；v1 女优资料保留。

`local_files` 核心字段：actress_id、path、path_key、scan_root_key、filename、normalized_code、manual_code、candidates、parser_rule_id、parse_status、is_present、first_seen_time、last_seen_time、last_seen_scan_id。actress_id + path_key 唯一；移除女优级联删除数据库记录，不操作视频文件。

`scan_history` 保存根目录与选项快照、状态、起止时间、发现数量、跳过链接数及最多 20 条目录错误。状态为 running / success / partial / failed / cancelled；异常终止留下 running 时，界面提示上次运行中断。

## 快照与失效规则

1. 完整枚举成功后，在一个事务内插入/更新观察到的文件并标记扫描范围内未见的旧记录。
2. 任意目录读取失败时，整份新快照不应用，保留旧记录。界面显示此次扫描失败/不完整的原因；不能用部分结果推断视频丢失。
3. 取消枚举或提交前收到取消信号，整次文件更新不提交；数据库最终提交已经完成后的取消不会撤销成功扫描。
4. 仅扫描顶层或缩小扩展名时，范围外记录维持其最后确认状态；再次完整扫描可重新确认。
5. 修改女优根目录会重置最近成功扫描时间。新根目录尚未成功扫描时，旧目录文件只在历史列表显示；新根目录成功扫描后，旧根目录记录标记为非当前。
6. 同路径重复扫描保留文件 ID 和人工修正；重新出现的同路径文件恢复有效。由于只读文件名，无法判断同路径内容是否被替换，因此人工修正同样保留，用户可手动清除。

## 识别与状态

自动识别是语法候选，不是已匹配作品库。无番号显示“无法识别”，多个不同候选显示“多个候选，待确认”。人工输入必须是一个受支持的完整番号。多个有效文件具有相同有效番号时，显示“同番号多个文件”，不会自动删除或宣称文件字节相同。

作品是否存在、女优归属、缺少、忽略、最新作品和完成度留待 Phase 3/4。不同目录文件不做内容哈希，也不推断移动关系。特殊未知编号暂需新增规则；当前不提供用户任意正则表达式执行界面。

## 已知边界

扫描结果列表和快照当前保存在内存，适合个人规模资料库；海量文件分页与虚拟化列表在 Phase 5 优化。取消在目录项间检查，操作系统若阻塞在网络盘读取，需等该读取返回。扫描不具备文件系统原子快照语义，扫描过程中移动文件可在下一次扫描校正。缓存/接口均无网络访问。
