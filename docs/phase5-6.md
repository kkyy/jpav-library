# Phase 5/6：日常使用与数据维护

首页按女优汇总已收录作品、需收藏数、已收藏数、缺少数、完成度、最新番号与最近更新。对尚未成功扫描当前目录的女优显示「待扫描」，避免把未知状态当作零收藏。排序包括最近更新、完成度、作品数和缺少数。全局搜索在本地 SQLite 中查女优常用名/日文名/别名、番号及标题，结果携带收藏状态和已匹配的本地路径，不把搜索词发给在线来源。

作品列表支持状态筛选、发行日期正反序、番号及首次收录时间排序。按用户要求扫描只读取视频文件名，因此不提供文件大小排序。封面仅在用户点击时从元数据 URL 下载，要求 HTTPS、限制图片 MIME/大小/尺寸，解码后存为缩略图；失败不影响作品库。

备份通过 SQLite backup API 取得一致快照，先写同目录临时文件，验证完整性后原子替换目标。恢复先检查 SQLite integrity_check 与迁移版本，再自动备份当前数据库；导入内容经 staging 验证后替换当前库，旧版本可按迁移升级。封面缓存不属于核心数据，可重新下载。恢复不会修改或删除视频文件。

日志写在本机 `logs/library.log`，最大 2 MB、保留 3 份轮转文件。事件记录作品和女优的内部 ID、数量与错误类型，不写 API 凭据或视频文件名。设置中的自动更新默认关闭；设为正数后定时刷新已绑定的 S1 来源，以及已绑定且配置了凭据的 DMM 来源。系统/`HTTPS_PROXY` 可用于代理。

Windows 打包脚本使用 PyInstaller 生成 onedir 目录；源环境仍可通过 `python -m av_library` 启动。打包完成不意味着外部 API 可用，真实 API 凭据、地区访问与来源完整度仍需用户环境验证。
