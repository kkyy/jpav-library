# Phase 3：作品元数据来源与同步

## 来源选择

可直接使用的来源是用户提供的 UTF-8 JSON/CSV 元数据文件。它可来自用户自行整理的公开作品目录。软件只读取元数据文件，不查找或下载视频，不将本地视频路径、文件名或内容发送到线上。导入文件本身的真实性和覆盖范围由用户确认。

在线来源包括无需凭据的 S1 官网目录，以及可选的 DMM/FANZA 官方 Affiliate v3 API。按女优日文名搜索完全同名的来源身份，再按来源 ID 分页读取作品。S1 会逐条读取官网详情页出演者，DMM 使用 ItemList 的 `iteminfo.actress`；演员名单缺失时拒绝同步，不会猜成单人作品。DMM 官方帮助说明需要申请 API ID，官方 SDK 说明 API ID、Affiliate ID 和女优/商品检索参数。DMM 在本环境仅用模拟 API 响应验证请求和解析，**没有声称在线接入已在真实账号或地区验证**。用户凭据仅从 `DMM_API_ID` / `DMM_AFFILIATE_ID` 环境变量读取；若 API 不可用，界面报告问题且不改作品库。

- [DMM Affiliate API ID 官方帮助](https://support.dmm.co.jp/affiliate/article/48053)
- [DMM Web Service 注册要求](https://support.dmm.com/affiliate/article/44077)
- [DMM 官方 SDK 的 ItemList 参数示例](https://github.com/dmmlabo/dmm-go-sdk/blob/master/docs/product.md)

DMM 官方帮助指出女优列表头像有肖像/版权使用限制，因此适配器不自动下载或显示该头像。作品封面只保存来源返回的 URL，本阶段不下载图片。DMM 商品列表不等于完整发行史，界面只显示“已收录”，不将来源总数当作全发行总数。

## 数据结构与身份

增量迁移 v3 新增 `providers`、`actress_sources`、`movies`、`actress_movies`、`movie_sources`、`sync_history`、`sync_items`。保留 v1/v2 所有资料、扫描记录及手动番号。`movies` 以 `namespace + code` 唯一；多人作品通过 `actress_movies` 多对多关系共享。来源外部 ID 独立存于 `movie_sources`，避免用其冒充标准番号；同一来源作品 ID 更换番号时拒绝自动改写。

每位女优每个来源至多绑定一个确认的来源身份；一个来源身份不能绑定多位本地女优。手动绑定时由用户选择候选；「自动检索单人作品」仅在恰好一个候选与日文名完全相符时自动绑定，重名或模糊匹配都留给用户确认。本地文件导入默认将所选女优作为文件来源的身份；不同路径视作不同来源，同一路径重导保持来源 ID 稳定。JSON/CSV 每份文件只归属一个本地女优，不能共用该路径导入给第二位。

电影元数据记录字段来源。首次非空值填入；同一来源之后可更新其原本提供的字段；另一来源给出冲突值时保留现值，避免静默互相覆盖。后续如需人工冲突裁决，应在 Phase 5 加入可视化审核。空字段不会清除已有值。

## 完整性与失败处理

同步先遍历所有页，校验游标不循环、来源 `complete` 标志、返回总数和每条番号，才在一个 SQLite 事务中更新作品库。至多 500 页；超出、网络错误、格式变化、取消或数据冲突都会保留原有作品库，并写入一条非成功历史。第一次成功同步标记为基线，不应把初始收录误报为近期新发行。同步不会删除本次未返回的历史作品：来源缩小覆盖范围、作品下架或暂时缺项都不能自动证明作品不存在。

同一部作品同时出现在多个来源时以标准番号合并；各来源的详情 URL 分开存。`first_seen_time` 保留首次发现时间，`last_update_time` 在接受元数据变更时更新，`last_synced_at` 只在完整成功的同步后更新。`sync_items` 记录本次新增/更新/未变，供 Phase 4 最新作品提醒使用。

## 文件格式

示例见 [actress_catalog.example.json](../examples/actress_catalog.example.json)。CSV 与 JSON 都支持中英文列名。`code`/`番号` 必填且必须是当前解析器支持的单一完整番号；`release_date` 按 ISO `YYYY-MM-DD` 解析。可选 `external_id` 为该文件来源的稳定作品 ID，不提供则使用标准番号。JSON 可以是数组或 `{"movies": [...]}`；CSV 首行为列名。UTF-8 BOM 可识别。整个文件先检查格式，错误时不导入部分作品。文件上限 50 MB。

当前导入只声明“本文件完整读取”，不声明该女优的完整发行史。用户如手动维护整份片单，可自行保证其覆盖范围；软件仍用“已收录”表述。在线 DMM 服务的覆盖范围也无法从本环境验证。

## 下一阶段边界

Phase 3 只建立作品元数据库；“已收藏/缺少/最新本地是否已有/完成度/忽略”在 Phase 4 通过文件记录和作品关联计算。由于用户要求只扫描视频文件名，Phase 4 匹配也不会读取视频内容。
